# Service pages

SVC-01 H1 — "[The Best per H1-04] [Service variant] in [Area entity]". No city.
SVC-02 Opening paragraph — a unique buyer state per page; never the same angle as another service page.
SVC-03 H2 How the service is delivered — process and timeline, under 500 tokens.
SVC-04 H2 Service types — H3 per sub-service (PG-01), under 500 tokens per H2.
SVC-05 H2 FAQ — "Frequently asked questions about [Service variant] in [Area entity]", H3 per question, questions unique to this page.
SVC-06 H2 Service areas — "[Service variant] service areas in [Area entity]", H3 anchor links to every location page.
SVC-07 CTA — phone, free estimate, no H tag.
SVC-08 No city name in any H tag.
SVC-09 Stays a detailed service page covering the service-entity cluster and real customer questions; never an informational blog post.
SVC-10 New content goes in as strong H3s inside existing sections, not thin new H2s.
SVC-11 Cited local facts allowed, never city-specific.
SVC-12 Back claims with local research without forcing content, overlapping other pages, or drifting from intent.
SVC-13 Max one table per page; checklists used conservatively.
SVC-14 Implementation copy labels every block H1 / H2 / H3 / paragraph / list / table.
SVC-15 Pages needing a full content optimization go into the handoff as `route: spo` (Service Page Optimizer). The build step does not rewrite them; their title, H1 and meta are still written (META-01).
SVC-16 Any placeholder (text or link) carries a visible `[PLACEHOLDER: reason]` note in the draft and a `placeholders` entry in the handoff.
SVC-17 Write routes: (A) brief → draft → approval → publish → Brand Guide write-back; (B) Paul writes → sanity check → approval → publish → write-back. Write-back runs LAST when it only adds information; anything a page needs from the Brand Guide is read at the brief stage.
SVC-18 Extra sections are allowed when content and entity depth justify them; usually via the Service Page Optimizer.
